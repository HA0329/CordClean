# 插件怎么用：被动插件、主动运行与持久化

> 这份文档回答一个常见问题：AI 工坊生成的插件装好之后，怎么真正用起来？
> 先给结论：**插件本身不“点一下就自己跑”，它是能力提供者；由扫描/清理/定时任务来驱动它。**

## 1. 插件不是独立 App

Cleaner 插件（内置或 AI 工坊生成）的职责是：

1. 通过 `ctx.cleaner.define(...)` 注册一个或多个清理任务；
2. 任务的 `scan(scan)` 只负责 **emit 候选**（路径/类型/大小）；
3. 真正删除始终由内核的补偿链 + 回收站/隔离区执行。

所以不存在“插件启动按钮”去启动一个常驻进程。插件启用后，任务就注册进内核，等扫描来调用它。

## 2. 被动插件：扫描时运行

适用：绝大多数清理插件（包括 AI 工坊生成的）。

手动使用：

1. 打开「插件」页，确认插件是「运行中」；
2. 打开「清理」页；
3. 在任务列表勾选该插件的任务（AI 生成插件默认 `defaultSelected: false`，不会自动勾选）；
4. 点「开始扫描」；
5. 在分组总览/逐项明细中确认结果，选择后清理。

从插件页也可以直接开始：

- 外部插件卡片点「**扫描此插件**」→ 跳到清理页并只扫描该插件的任务；
- 结果出来后仍按普通流程确认、清理。

## 3. 定时任务：真正的“主动运行”

适用：希望每天/每隔一段时间自动扫描，或授权后自动清理安全项。

1. 插件页对目标插件点「**加入定时任务**」；
2. 自动跳到「设置 → 定时任务」，并把该插件的任务预选进当前计划；
3. 设置间隔/每天时间，选择“只扫描并通知”或“自动清理安全项”；
4. 点「保存」；
5. 自动清理模式还需要点「授权自动清理」（规则或任务范围变化会使授权失效）。

定时任务插件才是“主动驱动者”；被驱动的仍然是普通清理任务。

## 4. 为什么没有“后台常驻主动插件”

外部插件运行在 worker 中，只能被主进程调用 `scan/clean`，不能：

- 主动把扫描结果推给界面；
- 主动请求内核删除；
- 自己决定什么时候清理。

这是安全设计：避免插件绕过「扫描 → 用户确认 → 补偿链 → 回收站/隔离区」。  
如果以后需要真正的后台生命周期（`activate/deactivate`、事件、定时器），需要新增权限模型与 UI，不属于当前版本。

## 5. 持久化与卸载

- 安装成功后会记录插件路径、启用状态和配置；
- 重启应用会自动重新加载（文件位于数据目录 `generated-plugins/`）；
- 卸载外部插件会释放任务/辖区，并删除工坊生成的文件与依赖目录；
- 安装失败、依赖下载失败、worker 加载失败会自动回滚删除本次生成文件；
- 启动时会清理没有持久化记录的工坊残留；
- 禁用插件后文件保留，可再次启用。

## 6. 依赖型插件

AI 工坊可声明 npm 依赖（如 `fast-glob`、`yauzl`）：

- 安装前必须在弹窗确认依赖清单；
- 依赖安装到 `generated-plugins/<name>/node_modules`；
- 安装时禁用 lifecycle scripts，但仍请注意：**依赖代码在 import 时拥有完整 Node 权限**；
- 卸载插件会删除依赖目录；npm/pnpm 全局缓存会保留（共享缓存）。
