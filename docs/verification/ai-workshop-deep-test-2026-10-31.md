# AI 建议与 AI 插件工坊深度验收（2026-10-31）

> 真实模型测试，不是 mock：使用用户本机已配置的 DeepSeek API Key（通过隔离数据目录注入，未打印 Key），真实扫描本机磁盘，真实生成/安装/卸载插件。
> 测试数据目录为临时副本，**未改动真实用户配置与文件**；测试结束后临时目录（含 Key 副本）已删除。

## 1. 测试环境

- Windows 11 IoT Enterprise LTSC 2024，AMD Ryzen 5 5600，16 GB；
- CordClean v0.6.7，Web 外壳（Edge + CDP 自动化），全新隔离数据目录；
- AI 顾问与 AI 工坊均启用，使用 `chat / deepseek-flash`，工坊独立 API 配置；
- 本机普通用户权限；真实清理盘存未执行（本次只测试分析建议、规则试运行/采纳、工坊生成与安装）。

## 3. 好的部分

- **AI 分析质量可用**：正确识别本机磁盘不紧张、无管理员权限、空目录/回收站收益有限；建议按“npm 缓存 / Edge 缓存 / 工具缓存 / 临时文件”分组，并给出可解释理由。
- **流式与可取消**：分析约 20 s，页面有运行态与取消按钮；直答路径能严格服从“只回复：收到”。
- **Vision 可用**：上传截图后模型准确描述了界面区块、控件与“API Key 已填写”等状态，并把截图信息纳入建议。
- **工坊流程完整**：生成 → 多文件审阅 → 静态校验 → 自动补齐清单 → 安装 → 概览卡片/客户端页面生效 → 卸载；widget 端到端成功。
- **安装事务可用**：widget 安装、卸载均正常，旧版本进 `.trash`；client 页面资源也能通过 `/plugin-assets/...` 正常返回。
- **默认安全边界没被破坏**：本次未执行批量实际清理；测试只采纳了隔离配置中的 AI 规则，真实配置未变。

## 4. 发现的问题（按严重程度）

### P0-1 AI 规则采纳可加入过宽的高风险规则，且默认选中

- AI 建议规则：`clear_dir %LOCALAPPDATA%/npm-cache`，标记 `risk=safe`；
- 试运行命中 385.4 MB，点击「采纳」后提示“规则已加入规则库并生效”；
- `settings.rules.custom` 实际写入：
  ```json
  {"id":"ai-...","category":"dev","name":"npm 缓存","risk":"safe",
   "target":{"type":"clear_dir","path":"%LOCALAPPDATA%/npm-cache"},"source":"ai"}
  ```
- 规则包新增任务 `rule:dev`，`defaultSelected=true`；如果用户随后一键扫描/清理，会清理整个 npm-cache，包括正在运行的 npx / AI 工具缓存。这与上游 PC-Cleaner 明确删除 npm-cache 父规则的安全决定冲突。
- 现状只有「试运行」和「采纳」两个动作，没有范围确认、敏感路径拦截或“采纳后不默认选中”。

**建议**：新增 AI 规则安全门：
1. 维护禁止/需二次确认的宽目录列表（`%LOCALAPPDATA%`、`%APPDATA%`、`%TEMP%`、盘符根、npm-cache 父目录等）；
2. AI 规则默认 `defaultSelected=false`，采纳后必须手动选择任务；
3. 采纳前显示“影响范围、是否会影响运行中程序、为何默认不选”；
4. 对 `safe` 风险但目标过宽的规则强制降级为 caution/risky 或拒绝。

### P0-2 工坊生成的 client 页面使用不存在的 bridge 协议，安装后页面无数据

- 实际宿主协议（`PluginsView.vue`）是：
  ```js
  { type: 'cordclean/plugin-page', method: 'resolve', id, resolverId, params }
  ```
  宿主回包为 `{ type: 'cordclean/plugin-page-result', id, ok, value }`；
- 生成的 `client/index.html` 发送的是：
  ```js
  { channel: 'cordclean/plugin-page', source: 'cordclean/plugin-page',
    type: 'cordclean/plugin-page', action: 'resolve', id, key, dataId, requestId }
  ```
  缺少 `method` 和 `resolverId`，宿主直接忽略；
- 页面最终显示“未检测到磁盘信息”，静态校验仍显示“清单、语法与静态契约校验通过”。

**建议**：
1. 在工坊 prompt 中提供宿主 bridge 的精确契约/小程序式 SDK；
2. 校验阶段检查 `client/index.html` 是否调用正确协议，或自动注入 bridge helper；
3. 增加“安装后打开 client 页面并 resolve 一次”的 E2E 测试；
4. 如果页面不需要宿主数据，应明确生成纯静态页面并标注。

### P1-1 清单 `engines` 兼容性没有在审阅阶段修正/报警

- 两个生成的 manifest 都写了 `"engines": {"cordclean": ">=1.0.0"}`，界面仍显示“兼容 >=1.0.0”；
- 实际安装时被 AI 包修复为 `^0.6.7`，说明后端知道要修，但审阅阶段没有提示；
- 用户会误以为包已兼容；若安装修复失败，将直接加载失败。

**建议**：审阅阶段按当前 `appVersion` 校验/自动修正 `engines`，把修复项显示为 warning，而不是只显示“校验通过”。

### P1-2 AI 推荐“新增扫描根”范围过宽

- AI 建议把整个 `C:\Users\<user>\AppData` 添加为扫描根（381 MB）；
- 按钮为“添加这些扫描根”，没有范围/性能/安全提示；
- 虽然需要用户确认，但这类根会显著扩大扫描范围。

**建议**：默认折叠为高级操作，显示预计扫描条目/耗时，禁止添加系统级/用户根目录，只允许具体应用目录。

### P1-3 流式阶段展示原始 JSON

- 分析进行中页面底部能看到 `{"items":[...],"rules":[...]}` 等原始结构文本（解析完成后才渲染为卡片）；
- 普通用户会以为是错误/乱码。

**建议**：流式阶段只显示“思考中/生成中”，解析完成后再显示结构化内容；调试模式再显示 raw。

### P2 其他

- AI 推荐项包含测试临时目录、截图目录、自己的 Edge profile；属于临时扫描结果，但建议过滤 CordClean 自身数据目录/截图目录，避免把工具自己的产物推荐清理；
- 工坊 client 页面生成耗时 66 s、widget 21 s；界面有“已等待 N 秒”，但没有阶段性进度，长等待时用户不知道是否卡住；
- 工坊安装后会清空审阅区（可接受，但建议保留最近一次安装记录/插件入口）。

### 需进一步复核

- 隔离配置首次启动时，工坊插件在配置 `enabled=true` 的情况下界面显示“未启用”；点击启用后 API Key 变为空；用同一配置重启后又恢复为“已配置”。本次未能在真实配置上稳定复现，建议单独验证“工坊插件启停时是否保留 Key”。

## 5. 结论

- AI 顾问：**可用且产出质量不错**，直答、Vision、分析速度都通过；但“AI 规则采纳”目前缺少安全闸门，属于上线前必须修的风险。
- AI 插件工坊：**widget 端到端成功**，多文件/client 页面安装链路也成功；但 client 页面 bridge 契约不匹配导致页面“装上了但没数据”，且校验未发现，这是工坊宣称能力的关键缺口。
- 本次测试未删除用户真实文件、未推送代码、未修改真实配置；隔离测试数据已删除。

## 6. 建议修复顺序

1. P0-1 AI 规则安全门（宽路径拦截 + 默认不选 + 明确确认）；
2. P0-2 client bridge 契约/SDK + 校验 + E2E；
3. P1-1 engines 审阅阶段修复/告警；
4. P1-2 扫描根高级化；
5. P1-3 流式 UI 与工坊长等待反馈。


## 7. 修复状态（v0.6.8）

- **P0-1 已修**：新增 AI 规则安全门（拒绝 npm-cache 父缓存、AppData/Temp/盘符根等宽目录；AppData 直系子目录降级 caution）；AI 规则采纳前二次确认；AI 来源规则/项不再默认选中；新增 6 项安全测试。
- **P0-2 已修**：工坊 prompt 写入精确 bridge 契约；校验阶段检查 client 页面 bridge，错误协议直接阻止安装；新增错误/正确协议测试。
- **P1-1 已修**：engines 自动修正并显示具体 warning；审阅区展示修正后的清单并用于安装。
- **P1-2 已修**：AI 扫描根保持逐项可选；AppData 等宽目录仍展示并默认勾选、标注“范围较大”，添加前二次确认（不强制过滤用户明确想加的目录）。
- **P1-3 已修**：流式原始 JSON 折叠到调试面板，普通视图只显示生成进度；工坊生成增加阶段提示（理解需求/生成清单代码/校验准备）与已等待秒数。
- 验证：全量 66 文件 / 483 用例通过；tsc/vue-tsc/build 通过。
- 已复验：修复后重新真实生成一次 client 插件，页面发送 `type: 'cordclean/plugin-page'`、`method: 'resolve'`、`resolverId`，校验通过（仅有 engines 修正 warning）；P0-1 的 npm-cache 采纳也被实际拒绝，具体 Edge 缓存规则可采纳且任务 `defaultSelected=false`。
