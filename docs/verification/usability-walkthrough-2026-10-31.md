# CordClean 真实用户走查报告（2026-10-31）

> 方式：全新配置（空 dataDir）启动，按普通用户路径实际使用：概览 → 扫描 → 选择 → 预演 → 实际清理 → 历史/撤销；另用桌面外壳启动核对原生界面。
> 未修改源码、未使用管理员权限、未做批量真实删除；实际清理只针对走查中自建的一个空目录，避免影响本机数据。
> 截图证据保存在本机临时目录（含本机路径，未纳入仓库）。
> 修复状态（2026-10-31）：P1-1～P1-4 已修复，见第 8 节；P2 问题仍待处理。

## 1. 环境与范围

- 系统：Windows 11 IoT Enterprise LTSC 2024，AMD Ryzen 5 5600，16 GB，普通用户；
- 运行：Web 外壳（Edge 无头 + CDP 驱动界面）+ Electron 桌面外壳（仅启动与首屏核对）；
- 数据：全新空数据目录，默认启用 8 个插件 / 38 个任务；
- 范围：核心清理闭环、任务/结果选择、预演与确认、历史与撤销、插件页、AI 两页、设置、日志查看器；
- 局限：单机、单次走查；未验证真实用户历史配置迁移、批量清理的真实文件删除、托盘/悬浮窗、管理员权限场景。

## 3. 做得好的地方

- **首屏明确**：概览直接回答“有多少任务、占了多少空间、能释放多少”；磁盘每 5 秒采样，数据不陈旧；
- **扫描性能很好**：17 个任务首次约 2.2 秒，热扫描约 1 秒；进度页明确展示文件/目录数、体积、权限受限数；
- **权限受限不静默**：59 条 EPERM 有明细入口，文案说明“不影响已发现项”，对普通用户友好；
- **风险默认策略合理**：安全项默认勾选，谨慎/高风险不勾选；有“受保护（不可清理）”单独视图；
- **预演与确认**：预演不会删除，确认弹窗明确列出项数、体积、风险分布；实际清理结果有失败/耗时/模式；
- **日志系统可用**：统一日志查看器可按级别/来源筛选、搜索、复制、打开目录，插件名与 RPC 日志都能看到；
- **可选能力有引导**：AI 插件未启用时给出“立即启用”；插件页状态（运行中/已停止、任务数、配置）清楚；
- **桌面外壳首屏正常**：与 Web 一致的界面，启动 314 ms，无崩溃。

## 4. 发现的问题（按优先级）

### P1-1 「去选择可清理项」不把用户带到结果区

扫描完成后点击“去选择可清理项”，页面视觉上仍停留在 38 个任务卡片顶部；结果选择区实际在页面下方约 1,700 px 处。实测点击前后 `.content` 的 `scrollTop` 都是 0，用户需要自己发现并向下滚动。

- 影响：用户会以为按钮无效，或把“任务勾选”误当成“结果选择”；这是核心闭环里最大的摩擦点。
- 建议：点击后滚动/切换到结果区；扫描完成后把任务选择区折叠为“重新选择任务”入口；或改成独立的结果页。

### P1-2 「撤销上次清理」的承诺与状态不一致

实际清理 1 项后，历史页“撤销上次清理”按钮仍高亮可点；点击提示“没有可撤销的清理记录（只保留最近一次）”。RPC `clean/undo-state` 明确返回 `available=false, recycle=1`，说明后端知道不可撤销，但前端未用这个状态禁用按钮。

- 影响：直接损伤“敢不敢清理”的信任，尤其在“默认删除方式：回收站（可还原）”的文案下。
- 建议：按 `available` 禁用按钮并给出原因（回收站模式/空目录/无隔离项），或在历史行上显示“可撤销/不可撤销”；不要把不可撤销记录展示成可撤销入口。

### P1-3 预演后的「继续清理」不会继续当前选择

预演完成页有“继续清理”按钮，但点击后返回任务选择页，选中项被重置为推荐集合（本次从自选的 1 项变回 181 项），并未带着原选择进入确认/实际清理。

- 影响：用户以为“继续”会执行同一批项目，实际要重新筛选，容易误清或放弃。
- 建议：保留预演时的 itemIds 直接进入实际清理确认；或把按钮改名为“返回选择项目”。

### P1-4 默认勾选 136 个空目录 + 把整个 `%TEMP%` 作为一个清理项

本次扫描的 136 个空目录全部在“推荐清理”默认选中，体积均为 0 B；“系统临时文件”里把整个 `%TEMP%` 作为一个 151.9 MB 的项上报，用户无法逐文件确认。空目录清理对释放空间没有贡献，却可能改变用户的目录结构；`%TEMP%` 整体清空又可能碰到运行中程序的文件。

- 影响：默认操作与“清理空间”的用户目标不完全一致；对普通用户存在非预期改动风险。
- 建议：空目录默认不勾选（或作为“高级清理”单独入口）；`%TEMP%` 拆成条目级扫描/展示（至少展示前 N 项 + 跳过占用中文件），并提供“只清理 N 天前”策略；默认只选“能释放空间且可重建”的项。

### P2-1 步骤条在尚未扫描时就把“选择”标为当前

全新数据目录第一次进入清理页，尚未扫描，步骤条已高亮第 2 步“选择”；扫描完成后同样高亮第 2 步。步骤状态没有准确表达“扫描→选择→清理”的进度。

- 建议：以 `scanResult` 是否存在、清理中/完成状态驱动 `active`；未扫描时只高亮“扫描”。

### P2-2 扫描/选择数字缺少对账

同一批结果页面出现：192 项/1.6 GB（扫描完成）→ 187 项/1 GB（可清理）→ 186 项/799 MB（推荐）→ 谨慎 1 项、受保护 5 项。数字本身可解释（5 项受保护、1 项谨慎未选），但界面没有一句话把它对上。

- 建议：在结果摘要处显示对账：“发现 192 − 受保护 5 = 187 可清理；推荐 186（799 MB）+ 谨慎 1（237 MB）= 1 GB”。

### P2-3 Web 外壳误显示「Electron Node」

Web 外壳概览系统信息同时显示 “Node 版本 24.22.1” 和 “Electron Node 24.22.1”；桌面外壳显示正确（系统 Node 24.22.1 / Electron Node 22.22.0）。原因是模板只比较 node 与 systemNode，未限定桌面外壳/electron 字段。

- 建议：只有 `state.app.shell === 'desktop'` 且 `appInfo.electron` 存在时才显示该行；Web 下隐藏或显示“—”。

### P2-4 38 个任务卡片过长，缺少搜索/折叠/风险筛选

清理首页是一个 38 卡片的长列表；要找到某个插件/任务只能滚动。选中 17 个任务的含义和影响也没有摘要（例如“预计扫描这些目录”）。

- 建议：按分类折叠、增加任务搜索、按风险/插件筛选；顶部显示“已选任务覆盖的体积/目录”摘要。

### P2-5 历史页信息偏少，且任务名显示内部 id

历史行显示任务列 `empty-dirs`（内部 id），没有“空目录”这样的用户可读名称；没有展开项、路径、失败原因或撤销状态。

- 建议：显示任务显示名；行可展开查看项目/失败明细；显示撤销可用性；失败项提供原因与定位。

### P2-6 AI 页面信息密度高、可选状态不够明确

AI 清理顾问启用后一次性展示接口形态、模型、推理等级、JSON、token、超时、评估器开关、Key、采集器、截图、补充说明；对第一次使用的用户认知负担较大。未配置 Key 时，顶部“开始分析”仍保持主按钮样式，禁用原因只在顶部标签中提示，需要更明确的禁用/引导。

- 建议：默认“简单配置”（接口/模型/Key） + “高级参数”折叠；未配置 Key 时把主按钮替换为“配置 Key”，并在按钮上明确 disabled 原因。

### P2-7 日志查看器只有时刻，没有日期；概览数据目录被截断

日志查看器行首为 `HH:mm:ss.SSS`，跨天查看无法区分日期；概览“数据目录”在窄列中被截断且无完整路径提示（设置页有完整路径）。

- 建议：日志行加日期或允许按日期筛选；数据目录按钮加 title/tooltip。

## 5. 总体判断

**核心能力可用，但还不是“普通用户可以放心一键清理”的状态。**

- 对技术用户：可以完成扫描→选择→预演→清理→查看历史，性能与透明度都不错；能接受当前的信息密度。
- 对普通用户：结果选择入口找不到、撤销承诺不一致、默认选中 0 B 空目录与整个临时目录，会造成“不知道选了什么/不敢点清理/点了没反应”的体验，建议在正式答辩演示前至少修掉 P1 的四个问题。
- 本次未发现崩溃、白屏或明显数据损坏；实际清理闭环成功，日志与诊断能力可信。

## 6. 建议的下一步（按投入产出排序）

1. **扫描完成后自动进入结果区/折叠任务区**（P1-1，改动小，收益最大）；
2. **用 `clean/undo-state` 驱动撤销按钮与历史状态**（P1-2，改动小，直接修复信任问题）；
3. **预演“继续清理”保留选择**（P1-3，改前端状态传递）；
4. **空目录默认不勾选 + `%TEMP%` 拆分/限制选择**（P1-4，涉及默认策略，需确认产品口径）；
5. **步骤条状态、数字对账、Web Electron Node、历史任务显示名**（P2，前端小改）；
6. 最后再做任务页折叠/搜索、AI 页面渐进式披露等体验优化。
