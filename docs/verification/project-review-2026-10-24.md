# CordClean 全项目复审（2026-10-24）

> 基线：v0.5.15（在本轮修复后发布）
> 范围：清理/扫描内核、回收站与安全链、插件框架、AI 工坊、UI 页面、文档与交付物。

## 1. 结论

本轮复审未发现新的高危删除/路径越界问题；清理链、扫描取消、隔离区、插件加载隔离与安全相关测试全部通过。

发现并修复的主要问题集中在**概览信息时效性**和**文档事实一致性**，并补充了轻量系统采样通道。

## 2. 本轮发现与修复

| ID | 严重度 | 问题 | 处理 |
|---|---|---|---|
| R-01 | 中 | 概览运行时长只随页面切换/手动刷新更新，看起来不是实时 | 运行时长每秒本地走时；内存 5 秒、磁盘/完整系统信息 60 秒自动采样；离开概览即清理定时器 |
| R-02 | 中 | “系统信息”曾把 Electron 内置 Node 22 显示为 Node 版本 | 优先显示系统 PATH Node，Electron Node 单独一行；每次进入概览/手动刷新重新检测 |
| R-03 | 中 | 完整 `system/info` 每次都会枚举磁盘，短周期刷新全部信息成本不必要 | 新增 `system/live` 轻量 RPC：只返回内存/运行时长，不枚举磁盘；概览按信息变化频率分别刷新 |
| R-04 | 低 | README/导师材料中测试文件数仍写 51/49，与当前 54 个测试文件不一致 | 统一为 54 个测试文件 / 385 个用例；缺陷记录引用统一为 D-01~D-62 |

## 3. 架构复核

### 清理链

- 扫描与清理分离，清理只接受用户勾选后的条目；
- 路径策略、辖区校验、补偿事务、隔离区、回收站回执链路保持原设计；
- 多任务清理进度使用 session 级状态：单任务 `finished` 不再提前关闭进度页；
- 回收站 PowerShell 脚本保持 ASCII-only，回执走 UTF-8 文件，避免编码乱码。

### 插件框架

- 原生插件未声明 `inject` 时按源码自动补齐（旧工坊产物兼容）；
- AI 工坊静态校验把“访问未 inject 的 ctx 服务”作为硬错误，生成失败会自动重试；
- 声明式卡片兼容 `string[]` / `{items}` / `{value: string[]}`，progress 兼容 resolver 返回的 `max`；
- 旧 command 的 `label` 作为 `title` 兜底显示。

### UI/状态

- 概览定时器在 `onUnmounted` 清理，不会切页后继续请求；
- 页面隐藏时跳过自动采样；
- 扫描/清理进度页与后台上任务解耦；切换侧边栏不会取消任务。

## 5. 剩余风险与边界

1. **AI 生成的插件是完整 Node 权限代码**，安装前仍需人工审阅；框架的静态校验只覆盖契约与 inject，不能证明业务逻辑安全。
2. **取消 AI 插件生成**目前只让前端等待失效，已经发出的模型 HTTP 请求不保证服务端立刻中断。
3. **系统缓存文件**（Explorer 持有的 `thumbcache_*.db` 等）可能仍无法放入回收站；当前策略是安全跳过并显示友好提示，不强制永久删除。
4. **Windows CI** 仍比本机慢，主要耗时在 GitHub Windows runner 冷启动与 385 个用例；本轮未改 CI 拆分。
5. 外部插件文件仍保留在用户数据目录，不纳入源码仓库；如需示例需单独脱敏后放入 `examples/`。
