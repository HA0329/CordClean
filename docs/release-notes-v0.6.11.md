# CordClean v0.6.11 发布说明

**发布日期：2026-11-23** · 前置版本：v0.6.10

本次更新集中在「长期可用」：补完侧边栏与 7 个功能区的交互基底、把内置插件逐个独立验证、统一图标与文案规范，并修掉一批真实缺陷（设置页标题乱码、工坊无法取消生成、AI 错误分类依赖文案、撤销清理失败只报数量等）。没有破坏性数据格式变更。

## 重点更新

### 侧边栏与 7 个功能区独立升级

- **侧边栏基底**：分组导航（开始/清理/扩展/智能/记录/系统）、`Ctrl/Cmd + K` 搜索、`Alt + 1..7` 区域快捷键、`Alt + ↑/↓` 循环切换、hash 深链接、折叠图标轨（68px ↔ 232px）、状态徽标（扫描中/清理中/插件异常/待恢复/未配置）、偏好持久化与坏数据容错；
- **概览**：骨架屏/错误重试/有缓存失败不白屏；快捷动作统一（刷新/复制摘要/一键扫描，不可用给原因）；磁盘 ≥90% 主动提醒并直达清理；最近清理摘要与空状态引导；自动采样只在窗口可见时进行；
- **扫描与清理**：同一次扫描结果下离开页面再回来恢复筛选/选择/推荐策略（新扫描才重置，24h 过期）；空结果分型（无内容/仅受保护/被筛选藏掉）各有引导；清理确认补充「预演不删除」「取消不丢选择」说明；
- **插件**：公共壳增加搜索、按状态筛选（运行中/已停止/异常/外部）、批量启用/停用/热重载（逐项执行并汇总失败）、异常插件错误堆栈与一键重试、外部插件能力/权限风险提示；**12 个内置插件逐个独立验证**（真实只读扫描审计 + 独立契约测试 + 单独提交），新增 `scripts/audit-plugin.ts`，`--clean` 模式可在审计沙箱内做真实清理（强制隔离区、不碰用户数据、清理后复核消失）；
- **AI 插件工坊**：准备状态引导（未启用/缺 Key/无模型/状态失败各有出口）；阶段化进度与结构化失败（截断/JSON 校验/凭据/超时/网络）；**「放弃生成」真正中断宿主 HTTP 请求**（新增 RPC `ai/workshop/cancel`，SSE/JSON 均可取消；取消失败才退回「丢弃迟到结果」）；本地草稿历史（去重/上限/容错）；安装前校验摘要按闸门归类 + 危险 API 命中；错误文本脱敏；
- **AI 清理顾问**：未配置/未启用/隐私关闭/缺模型/探测失败的引导态与一键出口；分析失败结构化分类 + 重试 + 技术详情折叠；**错误分类改为稳定错误码优先**（`error.data.aiCode` / IPC `[CODE]` 前缀，厂商改文案不再漂移，旧内核仍文案兜底）；流式输出在取消/失败时保留；
- **历史与隔离区**：历史筛选（任务/时间范围/结果类型/搜索）+ 排序 + 摘要；加载/空/筛选空三态；批量恢复/彻底删除/清空隔离区全部二次确认并写明可恢复边界，恢复逐条失败原因；历史↔隔离区关联、中断会话提示；**撤销上次清理的失败从「只报数量」升级为逐条「原始路径 — 失败原因」**（`clean/undo` 返回 `failures`）；修复旧实现把 API 失败当取消吞掉的问题；
- **设置**：分组/设置项搜索（多关键词 AND、只看未保存分组、命中跳转、Esc 清空）；未保存修改逐项「旧值 → 新值」+ 放弃修改二次确认；保存失败结构化原因 + 重试；危险项内联风险说明；字段来源角标（默认/已自定义/未保存）；恢复默认预览（会改哪些项、哪些不动）；危险变更保存前二次确认。

### 安全加固（v0.6.10 之后）

- 删除安全链：一次性清理令牌、执行前尺寸/时间复核、受保护目录名检查、大目录删除降级；
- 隔离区：清单防篡改、恢复目标路径必须仍在允许清理范围；startup/recycle 等维护性删除收敛到执行器内部通道；
- 隔离区恢复路径策略校验，installer/mover 的维护性删除收敛，避免绕过统一策略。

### UI 规范与缺陷修复

- 新图标体系：页面级标题统一为内联 SVG `SectionIcon`（与侧边栏 `AreaIcon` 同一视觉规范），覆盖概览/清理/历史/设置/AI/工坊与顶栏按钮；不再用 emoji 当标题图标；
- 修复设置页 11 个分组标题乱码（`[^<]*\` 正则片段被写入模板）；
- 全部原生 `<button>` 显式 `type="button"`（避免 `el-form` 内误提交）；插件卡「展开」按描述长度显示、左对齐并补 `aria-expanded`/`aria-controls`；
- 体积/时间展示统一 `@cordclean/shared` 的 `formatBytes` / `formatTime`（插件页不再出现 `1539.0 MB`、工坊不再拼 `1234KB`）；
- 新增静态回归 `tests/ui-template-integrity.test.ts`：标题禁正则/emoji、button 必须 type、禁手写 MB/KB、SectionIcon 引用校验。

- `pnpm test`：**95 个测试文件 / 716 个用例通过**（v0.6.10 为 69/489）；
- `pnpm build`：通过（UI + Electron 桌面外壳）；
- `pnpm docs:check`：通过；
- `node scripts/e2e-ui.mjs`：7 个页面渲染、侧边栏折叠/搜索/快捷键、扫描全链路通过，无 JS 异常；
- 内置插件逐个审计：12 个插件真实扫描契约违例 0；`--clean` 沙箱真实清理 large-files 3 项 / duplicates 1 项 / empty-dirs 1 项，清理后复核 0 残留；
- 本轮未涉及日志/性能路径，未重跑 `pnpm bench`，[基准文档](benchmark.md)仍为 v0.6.10 快照。

## 兼容性与升级注意

- 新增 RPC：`ai/workshop/cancel`（方法总数 72 → 73）；旧内核没有该方法时界面自动回退为「丢弃迟到结果」；
- AI 错误消息现在带 `[ERROR_CODE] ` 前缀（如 `[TIMEOUT]` / `[CANCELLED]`），界面会自动解析并去掉前缀；外部脚本若直接匹配原始错误文案需相应调整；
- `clean/undo` 返回值新增可选 `failures[{id,path,reason}]`，旧字段 `failed` 保留，向后兼容；
- 数据目录、设置结构、插件默认启用状态、清理/隔离/恢复安全限制均无破坏性变更；升级可直接覆盖安装/替换源码。

## 已知限制

- 工坊「放弃生成」只能中断进行中的请求；若宿主已返回结果，仍以序号丢弃，不覆盖当前草稿；
- AI 错误码依赖新内核；第三方/旧插件抛出的普通错误仍按文案规则兜底；
- 历史撤销的逐条失败原因需要新内核；旧内核只提供失败数量；
- 插件审计的 `--clean` 破坏性验证只对「扫描结果落在审计沙箱」的插件生效，系统类插件的删除安全由删除安全链测试覆盖；
- GitHub Release 依赖网络/凭据，若发布时网络受限则只推送 tag 与代码，Release 后续补建。
